## 1. Purpose

This note is the **contract** of each RTL module: what it computes, its
parameters and ports, its timing (latency, throughput) and its handshake.
It is the reference for assembling the modules in Phase 3.

The behavior of each module is defined bit-exactly by its fixed-point model
in `verif/models/filters_hw.py`; how this is verified is described in
VELA-TN-002. Resource usage and timing results are given by `make synth`
(VELA-NFR-002, VELA-NFR-004).

## 2. Common conventions

### 2.1 Clock and reset

| Item | Convention |
| :--- | :--- |
| Clock | single clock `clk`, 100 MHz from the PS `FCLK_CLK0` (VELA-NFR-001); all logic on the rising edge |
| Reset | `rst_n`, **active low, synchronous** (sampled on the rising edge) |
| Reset scope | control registers (`valid`, counters, state) are reset; pure data registers and line buffers are not (they map to RAM and their content is masked or overwritten) |

### 2.2 Pixel stream

- One pixel per transfer, **raster order** (row by row, left to right).
- Pixels are unsigned 8-bit (0-255); `grayscale` takes 3 × 8-bit RGB.
- A **frame** is `IMG_WIDTH × IMG_HEIGHT` pixels. Only the 3x3 filters need
  to know the frame size.

### 2.3 Handshake

| Signal | Direction | Meaning |
| :--- | :--- | :--- |
| `valid_in` | input | a pixel is present on the input bus |
| `ready_in` | output (3x3 modules only) | the module can accept a pixel |
| `valid_out` | output | a result is present on the output bus, for **one cycle** |

- An input pixel is **consumed** on a rising edge where `valid_in = 1` (and
  `ready_in = 1` for modules that have it). The source must hold the pixel
  until it is consumed.
- `valid_in` may drop at any time (gaps); the modules keep their state.
- **There is no `ready_out`:** outputs cannot be stalled. The downstream logic
  must accept every result on the cycle `valid_out = 1`.

### 2.4 Latency definition

**Latency** = number of rising edges between the edge that consumes a pixel
and the edge on which the downstream logic samples its result, **for a
continuous input stream**. Values below were measured in simulation
(VCD traces, `IMG_WIDTH = 8`) and match the formulas.

## 3. Module summary

| Module | Function | Input | Output | Parameters | Latency (cycles) | Uses |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `grayscale` | RGB → luminance | 3 × 8 bits | 8 bits | — | 1 | — |
| `threshold` | binary threshold | 8 bits | 8 bits (0 / 255) | `THRESHOLD` | 1 | — |
| `window3x3` | 3x3 window, zero padding | 8 bits | 72 bits | `IMG_WIDTH`, `IMG_HEIGHT` | `IMG_WIDTH + 3` | — |
| `gaussian_filter` | 3x3 Gaussian blur | 8 bits | 8 bits | `IMG_WIDTH`, `IMG_HEIGHT` | `IMG_WIDTH + 4` | `window3x3` |
| `sobel_filter` | 3x3 Sobel edges | 8 bits | 8 bits | `IMG_WIDTH`, `IMG_HEIGHT`, `MAG_SHIFT` | `IMG_WIDTH + 5` | `window3x3` |

## 4. grayscale

**File:** `rtl/grayscale.v` — **Model:** `grayscale_u8`

```
Y = (77·R + 150·G + 29·B + 128) >> 8
```

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `valid_in` | in | 1 | RGB pixel present |
| `r_in`, `g_in`, `b_in` | in | 8 | red, green, blue |
| `valid_out` | out | 1 | `y_out` valid |
| `y_out` | out | 8 | luminance |

- 77, 150, 29 = BT.601 coefficients (0.299, 0.587, 0.114) × 256, rounded;
  their sum is 256, so white (255, 255, 255) gives exactly 255.
- `+128` rounds to nearest: error vs the float golden model **< 1 LSB**
  (truncation alone reaches 1.31 LSB).
- Maximum sum 65 408 fits in 16 bits: no saturation needed.
- Constant multiplications become shift-and-add logic (no DSP).

## 5. threshold

**File:** `rtl/threshold.v` — **Model:** `threshold_u8`

```
Y = pixel_in > THRESHOLD ? 255 : 0
```

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `THRESHOLD` | 128 | 8-bit threshold, **strict** comparison (pixel = threshold → 0) |

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `valid_in` | in | 1 | pixel present |
| `pixel_in` | in | 8 | input pixel (typically grayscale) |
| `valid_out` | out | 1 | `pixel_out` valid |
| `pixel_out` | out | 8 | 0 or 255 |

Equivalent to the golden model `threshold(p / 255, T / 255) × 255` for every
pixel value. The threshold is fixed at synthesis time.

## 6. window3x3

**File:** `rtl/window3x3.v` — **Model:** `windows_3x3_u8`

Shared front-end of the three 3x3 filters. For each input pixel it outputs
the 3x3 neighborhood centered on that pixel, in the same raster order.

### 6.1 Parameters and ports

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `IMG_WIDTH` | 96 | frame width (≥ 2) |
| `IMG_HEIGHT` | 64 | frame height (≥ 2) |

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `valid_in` | in | 1 | pixel present |
| `ready_in` | out | 1 | pixel can be accepted (low during the flush) |
| `pixel_in` | in | 8 | input pixel |
| `valid_out` | out | 1 | `window_out` valid |
| `window_out` | out | 72 | 3x3 window, see §6.2 |

### 6.2 Output format

```
window_out = { w00, w01, w02, w10, w11, w12, w20, w21, w22 }    (w00 = bits 71:64)

        col-1  col   col+1
row-1 [  w00   w01   w02  ]
row   [  w10   w11   w12  ]      w11 = center = the current pixel
row+1 [  w20   w21   w22  ]
```

### 6.3 Borders

Neighbors outside the image (row −1, row `IMG_HEIGHT`, column −1, column
`IMG_WIDTH`) are **0**, like `np.pad(..., constant 0)` in the golden model.
The output frame has the **same size** as the input frame.

### 6.4 Structure and end-of-frame flush

- Two circular line buffers give, for each new pixel `k`, the pixels `k − W`
  and `k − 2W` of the same column; they have no reset (RAM inference).
- A 3x3 register array shifts on every step; its center is pixel `k − W − 1`.
- The center lags the input by `W + 1` pixels. After the last pixel of a
  frame, the module injects `W + 1` zero steps by itself to output the last
  row. **`ready_in` is low during these `W + 1` cycles**; the next frame
  starts once it rises again.
- Border masking uses the row/column position of the center.

### 6.5 Timing

| Item | Value |
| :--- | :--- |
| Latency | `IMG_WIDTH + 3` cycles |
| Throughput | 1 pixel/cycle, plus `IMG_WIDTH + 1` flush cycles per frame (≈ 1.6 % for 96 × 64) |

## 7. gaussian_filter

**File:** `rtl/gaussian_filter.v` — **Model:** `gaussian_u8`

```
Y = ( w00 + 2·w01 + w02 + 2·w10 + 4·w11 + 2·w12 + w20 + 2·w21 + w22 + 8 ) >> 4
```

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `IMG_WIDTH`, `IMG_HEIGHT` | 96, 64 | passed to `window3x3` |

**Ports** (shared by the three 3x3 filters):

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `valid_in` | in | 1 | pixel present |
| `ready_in` | out | 1 | pixel can be accepted (from `window3x3`) |
| `pixel_in` | in | 8 | input pixel |
| `valid_out` | out | 1 | `pixel_out` valid |
| `pixel_out` | out | 8 | filtered pixel |

- Weights 1/2/4 are wire shifts: adders only, no DSP.
- `+8` rounds to nearest: error vs the float golden model **≤ 0.5 LSB**.
- Maximum sum 16 × 255 + 8 = 4 088 fits in 12 bits; output ≤ 255.
- Latency: `IMG_WIDTH + 4` cycles (`window3x3` + 1).

## 8. sobel_filter

**File:** `rtl/sobel_filter.v` — **Model:** `sobel_u8`

```
Gx = (w02 + 2·w12 + w22) − (w00 + 2·w10 + w20)
Gy = (w20 + 2·w21 + w22) − (w00 + 2·w01 + w02)
Y  = min( (|Gx| + |Gy|) >> MAG_SHIFT , 255 )
```

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `IMG_WIDTH`, `IMG_HEIGHT` | 96, 64 | passed to `window3x3` |
| `MAG_SHIFT` | 0 | divides the magnitude by 2^`MAG_SHIFT` before saturation |

Ports: same as `gaussian_filter` (§7); `pixel_in` is expected to be grayscale.

- `|Gx|, |Gy| ≤ 1020` (12-bit signed); `|Gx| + |Gy| ≤ 1530` (11 bits).
- The 8-bit output **saturates at 255**. With `MAG_SHIFT = 0`, the output
  equals `clip(golden model, 0, 255)` exactly.
- The center pixel has weight 0 and is unused.
- **Two pipeline stages:** gradients are registered, then absolute values,
  sum and saturation. The single-stage version missed 100 MHz by 0.109 ns
  after place and route (see §12).
- Latency: `IMG_WIDTH + 5` cycles (`window3x3` + 2).

---

## 9. median_filter

**File:** `rtl/median_filter.v` — **Model:** `median_u8` (network `MEDIAN9_STAGES`)

```
Y = median(w00 … w22)      (5th of the 9 values once sorted)
```

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `IMG_WIDTH`, `IMG_HEIGHT` | 96, 64 | passed to `window3x3` |

Ports: same as `gaussian_filter` (§7).

- Median selection network "opt_med9": 19 compare-and-swap operations on 9
  levels, split into **3 pipeline stages** of 3 levels.
- Registers between stages: 9 values after stage 1, 3 after stage 2.
- Exact match with the golden model (the median of integers is an integer).
- The network is proven exhaustively (all 9! orderings, all 512 0/1 inputs).
- Latency: `IMG_WIDTH + 6` cycles (`window3x3` + 3).

## 10. Design decisions

| Decision | Modules | Reason | Alternative not chosen |
| :--- | :--- | :--- | :--- |
| Round to nearest (`+half` before the shift) | grayscale, gaussian | error < 1 LSB / ≤ 0.5 LSB for one adder | truncation (up to 1.31 LSB error) |
| Saturate at 255 | sobel | magnitude up to 1530; per-image normalization (as in the GUI) is impossible in a stream | fixed division (dims weak edges); `MAG_SHIFT` keeps it available |
| Zero padding, same-size output | 3x3 filters | identical to the golden model | border replication; cropped output |
| End-of-frame flush with `ready_in` | 3x3 filters | needed to output the last row with zero padding | relying on the next frame's pixels (would mix frames) |
| Single 8-bit channel | 3x3 filters | as specified; colour needs 3 instances or a grayscale stage | built-in RGB support |
| No DSP | all | DSP blocks are reserved for the CNN (VELA-NFR-004) | — |
| 3 pipeline stages | median | 9 compare levels in one cycle risks missing 100 MHz | single combinational stage |
| 2 pipeline stages | sobel | single stage measured at −0.109 ns slack at 100 MHz | single combinational stage |
| Synthesis-time parameters | all | simple, no configuration bus | run-time registers (AXI-Lite) |

## 11. Integration notes (Phase 3)

- **No output back-pressure.** The filters produce one result per cycle and
  cannot be paused. `oled_controller` consumes RGB565 pixels over AXI-Stream
  **with `tready`** and is limited by its SPI link: a frame buffer or FIFO is
  required between the filters and the display.
- **Colour formats.** The filters output 8-bit grayscale; the display expects
  RGB565 (16 bits). A conversion stage is needed (e.g. `{Y[7:3], Y[7:2], Y[7:3]}`).
- **Frame size.** The 3x3 filters must be instantiated with the actual
  `IMG_WIDTH` and `IMG_HEIGHT` of the processed image.
- **Chaining.** `grayscale` → `threshold` or → 3x3 filter is direct (same
  8-bit stream). But `grayscale` and `threshold` cannot be stalled: when they
  feed a 3x3 filter, the **source upstream of them** must stop while the
  filter's `ready_in` is low (end-of-frame flush), taking the pipeline
  latency into account, or pixels will be lost.
- **Clock.** `oled_controller` and `spi_master` take `CLK_FREQ` (default
  100 MHz, VELA-NFR-001); their delays and SCLK divider derive from it.

`make synth`: Vivado 2024.2, non-project mode, each module **out of context**

constrained with a 0 ns delay (assumed registered outside the module).

| Requirement | Result | Detail |
| :--- | :--- | :--- |
| VELA-NFR-002 | **PASS** | worst WNS +0.221 ns (`median_filter`) |
| VELA-NFR-004 | **PASS** | five filters: 725 LUT (1.4 %), 708 FF (0.7 %), 0 DSP |

Notes:

- **WHS** is the hold slack between internal registers (— : `grayscale` has
  no register-to-register path). Port-to-register hold is negative for every
  module (−0.25 to −0.50 ns): with a 0 ns input delay the tool assumes the
  input changes exactly on the clock edge, while the clock reaches the
  registers later through its routing. This is an artifact of the
  out-of-context setup; I/O hold is checked in the full design (Phase 3).
- **Line buffers:** the two 96-pixel buffers of `window3x3` map to half a
  BRAM tile (one RAMB18) plus 16 LUTs used as memory.
- **Fmax est.** = 1000 / (10 − WNS): an estimate for this module alone.
- **Smallest margin:** `median_filter` (+0.221 ns). It meets the requirement,
  but routing congestion in the full design could reduce it; a 4th pipeline
  stage is the fallback.
- The filter total counts one `window3x3` per 3x3 filter, as instantiated.
- `spi_master` / `oled_controller` rows: after the `CLK_FREQ` parameterization,
  the active-low reset change and the datasheet power-up sequence (§13).

## 13. Display path: spi_master and oled_controller

These two modules predate Phase 2a. They were verified with the same method
(VELA-TN-002) and aligned with the conventions of §2: **active-low
synchronous reset `rst_n`** (was active high) and **`CLK_FREQ` parameter**
(was 125 MHz hard-coded).

### 13.1 spi_master

**File:** `rtl/spi_master.v`

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `CLK_FREQ` | 100 000 000 | system clock (Hz) |
| `SPI_FREQ` | 6 250 000 | SCLK frequency (Hz) |

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `start` | in | 1 | pulse: send `data_in` (ignored while `busy`) |
| `data_in` | in | 8 | byte to send |
| `busy` | out | 1 | high during the transfer |
| `done_tick` | out | 1 | 1-cycle pulse at the end of the byte |
| `sclk`, `mosi` | out | 1 | SPI bus |

- **SPI mode 0**, MSB first: SCLK idles low, MOSI is set up before each rising
  edge (sampled by the slave) and changes after the falling edge.
- SCLK half period = `CLK_FREQ / SPI_FREQ / 2` cycles (8 at 100 MHz →
  6.25 MHz). SSD1331 limit: 150 ns minimum cycle (≈ 6.67 MHz).
- One byte = 16 SCLK half periods + 1 end step.

### 13.2 oled_controller

**File:** `rtl/oled_controller.v` — **Model:** `verif/models/oled_hw.py`

| Parameter | Default | Description |
| :--- | :--- | :--- |
| `CLK_FREQ` | 100 000 000 | system clock (Hz) |
| `SPI_FREQ` | 6 250 000 | SCLK frequency (Hz) |
| `POWER_UP_CYCLES` | `CLK_FREQ / 50` | wait after logic power-on (20 ms) |
| `RESET_CYCLES` | `CLK_FREQ / 10 000` | reset pulse and post-reset wait (100 µs; datasheet minimum 3 µs) |
| `VCC_ON_CYCLES` | `CLK_FREQ / 40` | panel supply settling before Display ON (25 ms) |
| `DISPLAY_ON_CYCLES` | `CLK_FREQ / 10` | SEG/COM turn-on after Display ON (100 ms) |

| Port | Dir | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk`, `rst_n` | in | 1 | clock, synchronous active-low reset |
| `s_axis_tdata` | in | 16 | RGB565 pixel |
| `s_axis_tvalid` | in | 1 | pixel present |
| `s_axis_tready` | out | 1 | pixel can be accepted |
| `oled_spi_sclk`, `oled_spi_mosi` | out | 1 | SPI bus to the Pmod |
| `oled_dc` | out | 1 | 0 = command, 1 = data |
| `oled_res` | out | 1 | display reset, active low |
| `oled_vccen`, `oled_pmoden` | out | 1 | panel and Pmod power enables |

Sequence:

Sequence (SSD1331 datasheet §7.9, same order as Digilent's `OLEDrgb_DevInit`):

```
rst_n released
 → pmoden = 1 (logic supply), vccen = 0, wait POWER_UP_CYCLES      (20 ms)
 → oled_res = 0 for RESET_CYCLES, then 1                          (100 µs)
 → wait RESET_CYCLES, send the 30 init commands (dc = 0)
 → vccen = 1 (panel supply), wait VCC_ON_CYCLES                    (25 ms)
 → send Display ON 0xAF (dc = 0), wait DISPLAY_ON_CYCLES           (100 ms)
 → s_axis_tready = 1
 → for each pixel accepted (tvalid && tready): send high byte, low byte (dc = 1)
```

Total power-up time at the default values: ≈ 145 ms. Unused state codes
return to the start of the sequence.

- **AXI-Stream with back-pressure:** `s_axis_tready` drops while a pixel is
  being sent. Throughput is limited by SPI. Measured in simulation at
  100 MHz: **281 cycles per pixel** (140 per byte), i.e. 2.81 µs; a full
  96 × 64 frame (6 144 pixels) takes **≈ 17.3 ms** (≈ 58 frames/s maximum).
- `oled_dc` is stable during each byte (checked by the SPI monitor).

> **Power sequencing — reviewed and aligned (2026-10-11).**
> The original module raised `oled_vccen` together with `oled_pmoden`, before
> the reset, and sent Display ON right after the init. It now follows the
> references:
>
> - **SSD1331 datasheet (Rev 1.2, §7.9):** VDD on → RES# low ≥ 3 µs, then high
>   → wait ≥ 3 µs → VCC on → once VCC is stable, send 0xAF (SEG/COM on after
>   100 ms). Power off: 0xAE → VCC off → wait t_OFF (typ. 100 ms) → VDD off.
> - **Digilent driver** (`vivado-library`, `PmodOLEDrgb.c`, `OLEDrgb_DevInit`):
>   PMODEN on, wait 20 ms → RES low 1 ms, high, wait 2 ms → init commands →
>   clear window → VCCEN on, wait 25 ms → 0xAF → wait 100 ms.
>   `OLEDrgb_DevTerm`: 0xAE → VCCEN off → wait 400 ms.
>
> The original sequence had worked on the Arty Z7-20 in the author's earlier
> project `fpga_sobel_edge_detection` (GitHub `Adebayo17`), with `oled_cs`
> tied low; the alignment removes the deviation from the datasheet.
>
> **Still differing from Digilent** (not unsafe, reset defaults apply): no
> command unlock (0xFD 0x12), pre-charge voltage (0xBB), VCOMH (0xBE), master
> current (0x87), contrast (0x81-0x83), scroll off (0x2E) or screen clear
> (0x25); **no power-off sequence** (0xAE, VCCEN off).
>
> SPI timing (Table 21) is met at 6.25 MHz: cycle 160 ns ≥ 150 ns, SCLK
> high/low 80 ns ≥ 75 ns (5 ns margin), data setup/hold ≈ 80 ns ≥ 40 ns.
> `oled_controller` has **no chip-select output**: CS must be tied low in the
> top level (single slave), so any SCLK glitch would desynchronize the byte
> framing until the next reset.
