## 1. Purpose

This note describes the CNN accelerator generated by Vitis HLS 2024.2 from
`hls/cnn_hw.cpp`: how it computes, how the PS (ARM) drives it through its
AXI4-Lite interface, how it is verified, and its latency and resources.
The fixed-point types are those of VELA-TN-004.

---

## 2. Architecture

```
AXI4-Lite ──► image window ──► local copy ──► conv1+ReLU+pool ──► pool1 (64x12x12)
 (control)    (0x1000)          img[3][24][24]   8 channels / cycle
                                                         │
               logits window ◄── FC 180x10 ◄── pool3 ◄── conv3+ReLU+pool ◄── pool2 ◄── conv2+ReLU+pool
               (0x20) + return    (argmax)     (20x3x3)   4 channels / cycle  (32x6x6)  8 channels / cycle
```

- **Fused convolution, ReLU and maxpool.** Each conv output is computed in an
  exact `acc_t` accumulator, rounded to its activation type, and merged with
  `max()` into the pool cells that contain it (1, 2 or 4 cells for 3x3
  windows with stride 2, TensorFlow SAME padding). The pool buffer is cleared
  to 0 before the layer, which also performs the ReLU. Conv outputs are never
  stored: only `pool1`, `pool2`, `pool3` are memories.
- **Output-channel parallelism.** `U` output channels are computed at once
  (`U` = 8 for conv1 and conv2, 4 for conv3): each input value is read once
  and multiplied by `U` weights held in `U` memory banks (weights cyclically
  partitioned on the output-channel dimension). The inner loop is pipelined
  at one iteration per cycle: `U` MACs per cycle, one DSP48 per MAC.
- **Local image copy.** The image is copied from the AXI4-Lite window into a
  local memory before conv1 (1 728 cycles). Reading the AXI4-Lite window
  directly from the conv1 pipeline made it 76 stages deep and raised the
  latency to 9.3 ms.
- **Weights** are ROMs initialized from `hls/generated/cnn_weights.h`,
  converted to `weight_t` (round to nearest) at synthesis time.
- **Result.** The class is the argmax of the exact FC scores (`ap_return`);
  the 10 logits are output as `logit_t` for the probability computed by the PS.

Sums are exact, so neither the summation order nor the fusion changes the
result: the IP is bit-exact with the TN004 model.

## 4. IP interface

One AXI4-Lite slave, bundle `control` (`ap_ctrl_hs` protocol). Register map
generated by Vitis HLS (`syn/verilog/cnn_hw_control_s_axi.v`):

| Offset | Content |
| :--- | :--- |
| `0x0000` | control: bit 0 `ap_start` (R/W, cleared on handshake), bit 1 `ap_done` (R, clear on read), bit 2 `ap_idle` (R), bit 3 `ap_ready` (R, clear on read), bit 7 `auto_restart` (R/W) |
| `0x0004` | global interrupt enable (bit 0) — not used |
| `0x0008` | IP interrupt enable: bit 0 `ap_done`, bit 1 `ap_ready` — not used |
| `0x000C` | IP interrupt status (toggle on write) — not used |
| `0x0010` | `ap_return`: predicted class, 0..9 |
| `0x0020`–`0x003F` | logits, 10 × 16 bits (`logit_t`, raw code / 2⁹), 2 per word |
| `0x1000`–`0x1FFF` | image, 1 728 × 16 bits (`input_t`, raw code / 2¹¹), CHW order, 2 per word |

**Packing (both windows):** word `n` holds element `2n` in bits 15:0 and
element `2n+1` in bits 31:16. Image element index = `(c × 24 + y) × 24 + x`.
The image uses 864 words (`0x1000`–`0x1D7C`); the logits use 5 words.

## 5. Software sequence (PS)

```
1. preprocess the image in float: center crop 24x24, per-image mean / std
2. convert each value to its input_t raw code:
       raw = clamp(floor(x * 2048 + 0.5), -32768, 32767)       (16-bit signed)
3. write the 864 packed words at base + 0x1000
4. write 1 at base + 0x0000 (ap_start)
5. poll base + 0x0000 until bit 1 (ap_done) is set        (~5.9 ms)
6. read the class at base + 0x0010
7. read the 5 logit words at base + 0x0020, unpack, logit = raw / 512
8. probability shown on the OLED = softmax(logits)[class]
```

- Step 2 must round **half up** and **saturate** exactly like
  `ap_fixed<16, 5, AP_RND, AP_SAT>`. Reference implementation:
  `input_raw()` and `pack_image_words()` in `verif/models/cnn_hw_model.py`,
  tested by `verif/tests/test_cnn_ip_interface.py`; the C code of Phase 3
  should be checked against them.
- `ap_done` is clear-on-read: poll it once per iteration and stop at the
  first read that returns it set.
- Vitis also generates a C driver (`xcnn_hw.h`) with the same accesses.

## 6. Verification

| Level | What | Result |
| :--- | :--- | :--- |
| C++ (g++ + Vitis headers) | `verif/tests/test_hls_cnn_hw.py`: bit-exact vs the TN004 model, 99.99 % agreement with the float golden model on 10 000 images | pass |
| C-simulation (Vitis) | `hls/testbench.cpp`, 20 images, bit-exact (class and logits) | 20 / 20 |
| C/RTL co-simulation (xsim) | same testbench on the generated RTL (AXI4-Lite interface included), 3 images | 3 / 3 |
| Interface contract | `verif/tests/test_cnn_ip_interface.py`: raw codes and packing | pass |

The testbench expected values come from `tools/gen_hls_tb_data.py`, i.e. from
the Python model, not from the C++ code.

## 7. Results and requirements

### 7.1 Latency

| Source | Cycles | At 100 MHz |
| :--- | ---: | ---: |
| Synthesis estimate (Vitis HLS) | 615 423 | 6.15 ms |
| **C/RTL co-simulation (measured on the RTL, 3 images)** | **598 350 – 598 420** | **≈ 5.98 ms** |

The measured latency varies slightly from one image to another: the number of
maxpool updates depends on the values. It includes the 1 728-cycle image copy;
the PS writes of the image (864 AXI4-Lite words) come on top and are to be
measured on the board (Phase 3).

### 7.2 Out-of-context implementation (Vivado 2024.2)

`make hls-impl`: the RTL generated by Vitis HLS is synthesized, placed and
routed alone on xc7z020clg400-1 with a 100 MHz clock (`tools/hls_impl.tcl`).

| Resource | Used | Available | % |
| :--- | ---: | ---: | ---: |
| LUT | 2 661 | 53 200 | 5.0 % |
| FF | 3 287 | 106 400 | 3.1 % |
| BRAM 36 Kb tiles | 41 | 140 | 29.3 % |
| DSP | 22 | 220 | 10.0 % |

Timing: **WNS +2.137 ns** (Fmax ≈ 127 MHz), **WHS +0.054 ns** between
internal registers. Port-to-register hold (−0.489 ns) is not meaningful out of
context (0 ns input delay vs routed clock, see `tools/synth.tcl`) and is
checked in the full design.

Vivado uses far fewer LUTs than the Vitis estimate (2 661 vs 11 732): the HLS
estimates are pessimistic, Vivado optimizes much of the control logic away.

### 7.3 Requirements

| Requirement | Criterion | Result | Evidence |
| :--- | :--- | :--- | :--- |
| VELA-NFR-006 | ≥ 99 % agreement with the float golden model | **PASS**, 99.99 % (10 000 images) | `test_hls_cnn_hw.py` |
| VELA-NFR-007 | generated RTL bit-exact with the C++ | **PASS**, 3 / 3 | C/RTL co-simulation |
| VELA-NFR-008 | latency ≤ 10 ms at 100 MHz | **PASS**, 5.98 ms | C/RTL co-simulation |
| VELA-NFR-009 | ≤ 50 % of DSPs, BRAMs, LUTs | **PASS**, 10 % / 29 % / 5 % | out-of-context implementation |
| VELA-NFR-010 | 100 MHz, WNS / WHS ≥ 0 | **PASS**, +2.137 / +0.054 ns | out-of-context implementation |

> **Memory note.** Vivado peaked at 3.1 GB during this implementation. On the
> 7.8 GB development machine, running the export and the implementation in
> one Vitis process (`export_design -flow impl`) exhausted the memory and
> `systemd-oomd` killed the whole terminal. The Makefile now runs each EDA
> tool in its own memory-capped systemd scope (`MEM_LIMIT`, default 4 GB) and
> keeps the export (Vitis) and the implementation (Vivado) separate.

## 8. Reproducing

```bash
make hls-test     # C++ vs models (g++), no Vitis needed
make hls-csim     # Vitis C-simulation (~1 min)
make hls-synth    # C-simulation + synthesis report (~3 min)
make hls-cosim    # synthesis + C/RTL co-simulation on 3 images
make hls-export   # synthesis + IP export (build/hls/cnn_hw_ip.zip)
make hls-impl     # export + separate Vivado OOC implementation, NFR-009 / NFR-010 check
```
