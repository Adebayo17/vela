## 1. Purpose

The HLS CNN computes in fixed point (`ap_fixed<W, I>`: `W` bits in total,
`I` integer bits including the sign, `W − I` fractional bits). For each
tensor this note answers two questions:

- **How many integer bits?** Enough to hold the largest value without
  overflow → from the measured value ranges (§3).
- **How many fractional bits?** Enough to keep the classification of the
  float golden model (VELA-NFR-006: same class on ≥ 99 % of the test images)
  → from a precision sweep (§4).

---

## 2. Method

`tools/cnn_fixed_point_analysis.py` runs a batched NumPy version of the CNN,
first checked against `python/cnn.py` (**10 000 / 10 000 identical
predictions**), then:

1. **Ranges.** Records min / max of every tensor on the CIFAR-10 test images,
   and for every accumulator a bound on its partial sums,
   `Σ |input × weight| + |bias|`, which no intermediate value can exceed
   whatever the summation order.
2. **Sweep.** Emulates the fixed-point CNN: weights and activations quantized
   to `ap_fixed<W, I>` with saturation, accumulators exact (as a wide
   `ap_fixed` accumulator is), for several widths and two quantization modes:
   - `trn`: truncation toward −∞ (`AP_TRN`, the `ap_fixed` default);
   - `rnd`: round to nearest (`AP_RND`).

   The integer bits `I` of each tensor come from step 1; the remaining bits
   are fractional. All weights and biases share one format.

> **Ranges must be measured on the whole deployment set.** On the first
> 1 000 images, `pool1` peaks at 13.5 (5 integer bits); on the 10 000 test
> images it reaches 23.95 (6 bits). Sizing on 1 000 images would have
> saturated activations on images the board will display.

- All weights and biases fit in `I = 3` (|w| < 4).

- The accumulators need at most 11 integer bits (conv2).

## 4. Precision sweep

### 4.1 Full sweep (1 000 images)

Agreement with the float model (same predicted class), weights × activations
widths, both modes. Integer bits from the 1 000-image ranges.

| weights W \ activations W | 8 | 10 | 12 | 14 | 16 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| **8**, trn | 43.5 % | 44.1 % | 43.9 % | 44.0 % | 44.0 % |
| **8**, rnd | 91.8 % | 95.7 % | 95.3 % | 95.3 % | 95.4 % |
| **10**, trn | 85.7 % | 87.2 % | 86.5 % | 86.8 % | 86.5 % |
| **10**, rnd | 93.1 % | 97.4 % | 97.7 % | 97.8 % | 97.8 % |
| **12**, trn | 92.1 % | 96.6 % | 96.5 % | 96.6 % | 96.5 % |
| **12**, rnd | 93.7 % | 98.1 % | 99.8 % | 99.9 % | 99.9 % |
| **14**, trn | 93.2 % | 98.3 % | 98.7 % | 98.8 % | 98.7 % |
| **14**, rnd | 92.9 % | 98.9 % | 99.9 % | 100.0 % | 100.0 % |
| **16**, trn | 93.0 % | 98.3 % | 99.3 % | 100.0 % | 99.8 % |
| **16**, rnd | 93.4 % | 98.2 % | 99.8 % | 100.0 % | 100.0 % |

**Truncating the weights is very costly at small widths** (8 bits: 44 %
agreement with truncation, 92-96 % with rounding). The weights are
constants: they can be **rounded once, offline**, at no hardware cost.

Float golden model on the same 10 000 images: **74.5 %** (76.0 % on the
first 1 000). All candidates meet VELA-NFR-006 (≥ 99 %) and VELA-FR-005

## 5. Chosen types

**16-bit weights and activations, round to nearest, saturation.**

- 100 % agreement on the 10 000 test images: maximum margin over the 99 %
  requirement, so later optimizations do not start at the limit.
- A Zynq DSP48E1 multiplies 25 × 18 bits: a 16 × 16 product uses **one DSP**,
  exactly as a 12 × 12 one would. Going below 16 bits saves memory, not DSPs.
- Memory stays small: weights 27 846 × 16 bits ≈ 54 KB.

| Type | `ap_fixed` | Range | Resolution | Used for |
| :--- | :--- | :--- | :--- | :--- |
| `input_t` | `<16, 5, AP_RND, AP_SAT>` | ±16 | 2⁻¹¹ | normalized input image |
| `weight_t` | `<16, 3, AP_RND, AP_SAT>` | ±4 | 2⁻¹³ | all weights and biases |
| `act1_t` | `<16, 6, AP_RND, AP_SAT>` | ±32 | 2⁻¹⁰ | conv1 output after ReLU, pool1 |
| `act2_t` | `<16, 7, AP_RND, AP_SAT>` | ±64 | 2⁻⁹ | conv2 output after ReLU, pool2 |
| `act3_t` | `<16, 7, AP_RND, AP_SAT>` | ±64 | 2⁻⁹ | conv3 output after ReLU, pool3 |
| `acc_t` | `<40, 14>` | ±8192 | 2⁻²⁶ | all accumulators (conv and FC) |
| `logit_t` | `<16, 7, AP_RND, AP_SAT>` | ±64 | 2⁻⁹ | FC outputs |

Notes:

- **Accumulator exactness.** A product `input_t × weight_t` has 11 + 13 = 24
  fractional bits (at most; 23 or 22 for the other layers). `acc_t` keeps
  26 fractional bits, so every product and sum is exact, and 14 integer bits
  (needed: 11). 40 bits fit the 48-bit DSP48 accumulator path.
- **Quantization points.** Activations are quantized once per output value,
  after the accumulation (not after each MAC): rounding costs one adder per
  output, not per MAC.
- **ReLU then pool in the activation type.** Rounding and saturation are
  monotonic, so quantizing the conv output before or after ReLU / maxpool
  gives the same result; the conv output can be stored directly as `actN_t`.
- **Weights** are converted from the float32 values with `AP_RND`
  (round to nearest), offline: no hardware cost.
- **Saturation** (`AP_SAT`) bounds the error on images outside the measured
  ranges instead of wrapping around (the `ap_fixed` default `AP_WRAP`).

## 6. Design consequences

- **Preprocessing.** The CNN expects the **normalized** image (center crop,
  then per-image mean / standard deviation). The normalization needs a full
  pass over the image and a square root: proposed on the PS (ARM, float),
  which then writes `input_t` values to the IP. To be confirmed when defining
  the IP interface.
- **Softmax.** The classification only needs `argmax(logits)`. The
  probability shown on the OLED (e.g. "CAT 74%") can be computed by the PS
  from the 10 logits, avoiding `exp()` in hardware. The IP outputs the logits
  and the predicted class.
- **Possible optimizations (step 4)**, not needed by VELA-NFR-006:
  12-bit types (99.5 % agreement) to halve the weight memory; unsigned types
  for the post-ReLU activations (one more fractional bit).

## 7. Reproducing the analysis

```bash
# Candidates on the 10 000 test images (~3 min)
python tools/cnn_fixed_point_analysis.py --images 10000 \
       --configs 16:16:rnd,14:14:rnd,12:12:rnd,16:16:trn \
       --report build/cnn_fixed_point_10k.md

# Full sweep 8..16 x 8..16 x {trn, rnd} on 1 000 images (up to ~20 min)
python tools/cnn_fixed_point_analysis.py --images 1000
```

Also available as `make cnn-fixed-point` (candidates on 10 000 images).
Reports are written to `build/` (not tracked).
